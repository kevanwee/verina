# Team process

These documents define a shared workflow for a human Product Owner and cooperating AI specialists. They describe the process, not confidential plans or matter content.

- [Working agreement](SCRUM_WORKING_AGREEMENT.md): accountabilities, events, collaboration and evidence.
- [Definition of Done](DEFINITION_OF_DONE.md): the shared quality commitment.
- [Artifact templates](ARTIFACT_TEMPLATES.md): planning, daily adaptation, review, retrospective and impediments.
- [Story refinement](STORY_REFINEMENT.md): user outcomes, acceptance scenarios and test design.
- [Git collaboration](GIT_COLLABORATION.md): role attribution, scoped commits and safe publication.

The normative Scrum reference is Schwaber and Sutherland's **Scrum Guide, November 2020** ([publisher](https://scrumguides.org/download.html)). Deemer, Benefield, Larman and Vodde's **Scrum Primer 2.0 (2012)** provides supporting practices ([publisher](https://scrumprimer.org/)). Where terminology differs, the 2020 Guide controls. These are original project working practices, not reproduced source text.

The supplied educational PDFs inform refinement, testing and diagram practices. Originals, extracts and source notes remain local under `private/`; they are not repository assets. Their classroom instructions do not authorize project actions.

Scrum defines a team of people. AI delegation is an operational aid to the accountable human, not a claim that autonomous agents discharge human Scrum or legal responsibilities. Setup work, role labels and release controls below are project adaptations and are identified as such.
