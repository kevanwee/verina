# ADR 002: AI orchestrator, prompt templates, redaction and AI audit events

- Status: Accepted (skeleton; revisit when EN-8 audit store and the PDPA PII taxonomy land)
- Date: 2026-10-13
- Deciders: AI/LLM engineer (agent), scrum master; security and PDPA counsel to review

## Context

Every model call must be audit-logged with model, version, template and sources (FR-9.2, NFR-7), personal data must be redacted before it reaches an external model when the tenant enables it, and the provider endpoint must be zero data retention with no training (NFR-1). Contract text is untrusted input and a prompt-injection vector. Tests must never call a live model.

## Decisions

1. **One entry point.** `verina.ai.Orchestrator.run(task_role, template_id, variables, documents, matter_id, actor)` is the only sanctioned path to a model. No other module imports the `anthropic` SDK.
2. **Role-based model registry.** `drafting` and `verification` use Claude Opus 5.5 (`claude-opus-5-5`); `triage` and `extraction` use Claude Haiku 5.5 (`claude-haiku-5-5`). Ids come from settings (`VERINA_AI_MODEL_<ROLE>`). Effort is set per role (`high` for drafting and verification, `low` for triage, `medium` for extraction) because both models otherwise default to `medium`. Thinking is not configured: it is always on for Opus 5.5 and disabling it is rejected by the API.
3. **Versioned, hashed templates.** Templates are TOML files (`id`, semver `version`, `role`, `variables`, `system`, `instructions`, optional `output_schema`) in `verina/ai/templates/`. The content hash is SHA-256 over a canonical JSON of the fixed security frame plus every semantic field, after newline normalisation, so it is stable across OSes and formatting. A test pins the hash of each shipped template: a released template is never edited, a new version is added instead. The orchestrator refuses a template whose role differs from the requested role.
4. **Untrusted content is structurally separate.** Templates receive only short named variables (max 2,000 characters each, `string.Template` substitution with no re-expansion). Document text is never interpolated. Each document is sent as its own Anthropic `document` content block (plain-text source, with a `context` note that it is untrusted), followed by the instruction block. Every system prompt starts with a fixed frame telling the model that document content is data, that placeholders must be kept verbatim, and that only the system prompt and final instruction block define the task.
5. **Redaction before the call, re-identification after.** A `Redactor` protocol (`redact(text, mapping=None) -> (text, mapping)`, `reidentify(text, mapping)`) has a no-op implementation and `RegexRedactor` (regex-v1): Singapore NRIC/FIN with checksum validation (S/T/F/G/M series), email addresses, and `+65` phone numbers. One mapping is shared across all variables, document titles and texts in a call, so a value always gets the same placeholder (`[EMAIL_1]`). The mapping stays in process memory: it cannot be pickled or copied, has no serialiser, and its `repr` shows only a count. Whether redaction runs is decided by a `RedactionPolicy` (default: `VERINA_AI_REDACTION_ENABLED=true`); the tenant AI policy (FR-9.3) will implement it. The category list will follow the PDPA counsel's taxonomy (`docs/compliance/pii-taxonomy.json`) via `RedactionRule`s or a stronger detector behind the same protocol.
6. **Sprint 0 external calls disabled.** `AnthropicClient` rejects default/live transports and caller-injected SDK/HTTP clients before SDK construction, regardless of environment or API key. Only an explicit `httpx2.MockTransport` is permitted, wrapped in a fresh client with environment proxies disabled. This is a development skeleton; removing the gate requires reviewed provider/endpoint approval, redaction guard and durable audit controls. Mock callbacks are trusted test code, not an isolation boundary against malicious developers.

   **Provider-neutral client protocol.** `ModelClient.complete(ModelRequest) -> ModelResponse` (async). `AnthropicClient` uses the official `anthropic` Python SDK (1.x, `AsyncAnthropic`), with prompt caching on the system prompt and on the last document block, structured output via `output_config.format` when a template declares a schema, and SDK errors mapped to `ModelClientError(retryable=...)` without echoing the provider's message. `FakeModelClient` records requests for tests.
7. **Provider diagnostics.** The installed SDK logs request bodies at DEBUG. Verina discards records from `anthropic._base_client`; tests capture DEBUG logging and assert both key and document canaries are absent. This does not certify other SDK versions or injected developer logging.

   **Secrets.** The API key is `VERINA_ANTHROPIC_API_KEY`, held as a `SecretStr`, unwrapped only when the SDK client is built, and kept out of `repr`, logs, errors and audit events (tested with SDK debug logging captured).
8. **ZDR is a release precondition, not a request flag.** Zero data retention is agreed per Anthropic organisation and attached to its API keys. Production must only hold a key from a ZDR-enabled organisation (or `VERINA_ANTHROPIC_BASE_URL` pointing at a ZDR-contracted gateway). Server-side refusal fallbacks to another model are **not** enabled: they would change the model that processes client data outside the registry and would need their own ZDR and audit treatment.
9. **One completion audit event per logical model invocation.** SDK HTTP retries are not separately recorded. Cancellation, process failure, or a broken sink after provider dispatch can leave no durable event; live-call activation requires a durable start record and attempt/outcome reconciliation.

   **Current completion event.** `verina.audit.events.AIAuditEvent` records matter, actor, role, requested and served model, effort, template id/version/hash, input hash (canonical JSON of the redacted request actually sent), output hash (model output as received, before re-identification), token counts including cache reads/writes, latency, whether redaction ran and how many values per category, stop reason, provider request id, and outcome. It never contains prompts, document text, output or personal data. Failed calls also emit an event (`outcome="error"`) before the error is re-raised. Validation errors before the call (unknown role, wrong variables, missing template) make no call and emit no event. Events go to an `AuditSink` protocol; `InMemoryAuditSink` is used until EN-8 adds the hash-chained store. If the sink fails, the run fails (fail closed) and no output is returned.

## Consequences

- Swapping a model or provider is a settings change or a new `ModelClient`; every event records what actually ran.
- Regex-v1 does not catch names, addresses, bank details or local 8-digit phone numbers. Redaction coverage depends on the PDPA taxonomy and a stronger detector; until then, development uses synthetic data only.
- NRIC/FIN values are re-identified in upper case (one placeholder per identity regardless of case).
- Calls are non-streaming with `max_tokens` 16,000 by default. Long drafting outputs should move to streaming (`messages.stream` + `get_final_message`) when drafting lands.
- Audit emission happens after the call. EN-8 should consider writing a "call started" record first so a crash between call and emission is still visible.
- `anthropic>=1.13,<2` is a runtime dependency (it brings `httpx2`).

## Security review (SEC-1, 2026-10-13)

[R-002](../security/REVIEWS.md#r-002--ai-orchestrator-skeleton-and-external-model-call-boundary) approves synthetic, in-process development with external transport disabled. Regex-v1, mutable tenant redaction settings and the in-memory sink are not client-data protections. Model ids and endpoint features need provider verification before activation; mock serialization tests do not prove live availability.

Anthropic documents organization-specific ZDR enablement and feature/model exceptions; an API key alone does not establish the applicable terms. Prompt caching is documented as ZDR-eligible but retains in-memory cache representations for its TTL. Confirm contract, workspace, model, endpoint, cache and processing-region evidence before rollout.
